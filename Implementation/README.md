# Implementation Records

`Plan/` contains the intended architecture and phase specifications. This folder records what was actually built, how it was validated, and any differences from the plan.

After each phase, add a report in `Phases/` using `Phases/PHASE_TEMPLATE.md`. Include completed scope, key design decisions, changed files, exact checks and results, required manual tests, known limitations, deviations, and handoff notes. Keep claims evidence-based; mark checks as not run when they were not run. Do not mark a phase complete until its acceptance criteria are met or explicitly documented as deferred.

At each reviewable milestone, provide the user a concise summary, copyable test steps, and a suggested detailed commit message. The user decides when to commit.
